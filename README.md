# SkinRag — کاتالوگ و مشاوره پوست، مو و زیبایی

Web API با .NET 8، SQL Server و مدل‌های محلی Ollama. داده نمونه ساختگی است و برای تست جست‌وجو و فیلترها طراحی شده است؛ برند، قیمت، فرمول و موجودی واقعی نیستند. تمام قیمت‌ها **ریال (IRR)** هستند.

## خط پردازش جدید مشاوره

پیاده‌سازی، قرارداد API، محدودیت‌های مدل و دستورهای بررسی در [راهنمای خط پردازش](docs/consultation-pipeline.md) توضیح داده شده‌اند. کنترلر از `ConsultationService` استفاده می‌کند؛ تشخیص نیت، ساخت query، بازیابی و اعتبارسنجی پیشنهادها جدا شده‌اند. نام برندهای فعلی از فهرست تأییدشده کاربر گرفته شده است؛ بخش‌های مربوط به generator در ادامه داده اولیه را توصیف می‌کنند.

## داده‌های نمونه

- ۳۶۰ محصول جدید: ۱۲۰ پوست، ۱۲۰ مو، ۱۲۰ زیبایی و آرایش؛ همراه ۳ محصول نمونه اولیه.
- ۴۵ زیردسته و ۳ دسته اصلی، ۸ برند ساختگی و برند نمونه قبلی.
- ۱٬۰۸۰ تنوع با اندازه، رنگ، finish، قیمت، موجودی و وضعیت فعال مستقل.
- ۱۳ پروفایل پوست/مو، ۳۱ نیاز مراقبتی و ۲۲ ترکیب با نام فارسی و INCI.
- نمونه‌های ناموجود، غیرفعال، بدون عطر و دارای عطر برای سناریوهای مرزی.

## راه‌اندازی

نیازمندی‌ها: SDK سازگار با .NET 8، SQL Server، ابزار `sqlcmd` و Ollama. Python فقط برای بازتولید داده یا اجرای تست‌ها لازم است؛ اجرای API به Python نیاز ندارد.

۱. رشته اتصال `SkinRag.Api/appsettings.json` را تنظیم کنید. تنظیمات محیطی مانند `ConnectionStrings__DefaultConnection` بر فایل مقدم هستند.

۲. اگر دیتابیس جدید است، ابتدا `database/sample.sql` را اجرا کنید. برای دیتابیس فعلی که جدول Products دارد، این مرحله را رد کنید.

۳. ارتقای ساختار و افزودن داده‌های آزمایشی با رشته اتصال برنامه:

```powershell
powershell -ExecutionPolicy Bypass -File database/upgrade.ps1
```

`upgrade.sql` افزایشی و تراکنشی است. `seed-demo.sql` فقط رکوردهای جدید را درج می‌کند؛ اجرای مجدد SKU تکراری نمی‌سازد. محصول‌های قبلی و شناسه‌هایشان حفظ می‌شوند. برای ارتقای ساختار بدون داده آزمایشی، `-SkipDemo` بدهید. ابزار کمکی با Windows Authentication کار می‌کند؛ در حالت SQL Authentication، فایل‌های SQL را با ابزار و اعتبارنامه مجاز خود اجرا کنید.

۴. مدل‌های تنظیم‌شده را آماده کنید:

```powershell
ollama pull nomic-embed-text
ollama pull qwen2.5:7b
```

۵. اجرا:

```powershell
dotnet run --project SkinRag.Api
```

Swagger در محیط Development روی `/swagger` در دسترس است. پروفایل اجرا از `https://localhost:63838` و `http://localhost:63839` استفاده می‌کند. برای اجرای آزمایشی HTTP بدون پروفایل:

```powershell
dotnet run --project SkinRag.Api --no-launch-profile -- --urls http://127.0.0.1:52783 --environment Development
```

## دیتابیس

| جدول | کاربرد |
|---|---|
| Products | اطلاعات پایه و فیلدهای متنی قبلی برای سازگاری |
| Categories | دسته‌های اصلی و زیردسته‌ها با Domain و ParentId |
| Brands | برندها و برچسب آزمایشی |
| Profiles / ProductProfiles | نوع پوست و مو و ارتباط چندبه‌چند |
| Concerns / ProductConcerns | نیازهای مراقبتی و واژه‌های جست‌وجو |
| Ingredients / ProductIngredients | ترکیبات فارسی/INCI و فیلتر حذف ترکیبات |
| ProductVariants | SKU، اندازه، رنگ، finish، قیمت و موجودی مستقل |
| ProductEmbeddings | بردار ذخیره‌شده، مدل، ابعاد، هش محتوا و زمان تولید |

روی SKUها، کلیدهای ارتباطی و مسیرهای جست‌وجوی موجودی ایندکس وجود دارد. قیمت و موجودی منفی، اندازه غیرمثبت، واحد نامعتبر و JSON نامعتبر بردار با قیود دیتابیس رد می‌شوند. در محصول دارای تنوع، قیمت و موجودی ProductVariants مرجع انتخاب است؛ فیلدهای تجمیعی Products صرفاً برای سازگاری هستند.

برای محصولات قدیمی بدون تنوع، قیمت و موجودی همان Products استفاده می‌شود. محصول با فرمول نامشخص در فیلتر حذف ترکیبات پذیرفته نمی‌شود. نبود یک ترکیب در داده ثبت‌شده، تضمین ایمنی در برابر حساسیت نیست.

## API

| مسیر | کاربرد |
|---|---|
| GET /api/catalog/filters | دسته‌ها، برندها، پروفایل‌ها، ترکیبات، نیازها، رنگ‌ها و finishهای معتبر |
| GET /api/catalog/stats | آمار دسته‌ها، محصولات فعال/موجود و تنوع‌ها |
| GET /api/catalog/products | فهرست صفحه‌بندی‌شده و فیلترشده |
| GET /api/catalog/products/{id} | جزئیات محصول و تنوع‌های فعال، شامل ناموجودها |
| POST /api/consultation/ask | مشاوره با اطلاعات فعلی دیتابیس و امتیاز بازیابی |
| GET /api/knowledge/status | آمادگی، پیشرفت بازسازی و تعداد بردارهای بازیابی‌شده از کش |
| POST /api/knowledge/rebuild?force=false | بازسازی دستی با کلید مدیریت |
| GET /health/live | زنده بودن فرآیند |
| GET /health/ready | آمادگی اتصال SQL و ایندکس؛ تا آماده شدن پاسخ ۵۰۳ |

فیلترهای مشترک: `domain` (`skin`, `hair`, `beauty`)، `categorySlug`، `brandSlug`، `skinType`، `hairType`، `concernSlug`، `minPrice`، `maxPrice`، `shade`، `finish`، `sizeValue`، `sizeUnit`، `fragranceFree` و `excludeIngredientSlugs`.

نوع پوست/مو را با نام فارسی یا slug موجود در filters ارسال کنید. categorySlug دسته اصلی، زیردسته‌های آن را هم شامل می‌شود. `Concern` در مشاوره متن آزاد است؛ `ConcernSlug` فیلتر قطعی است. در GET آرایه حذف ترکیبات را با تکرار پارامتر بفرستید، مثلاً `excludeIngredientSlugs=fragrance&excludeIngredientSlugs=shea`.

پارامترهای فهرست: `search` (نام، کلیدواژه یا SKU)، `page` و `pageSize` (حداکثر ۱۰۰)، `inStockOnly` (پیش‌فرض true). تمام فیلترهای قیمت/رنگ/اندازه/موجودی باید برای **یک تنوع واحد** برقرار باشند. فقط تنوع‌های مطابق فیلتر در نتایج فهرست و مشاوره نمایش داده می‌شوند.

### نمونه مشاوره

```json
{
  "question": "برای موی فر و وز یک کرم مو بدون آبکشی می‌خواهم",
  "domain": "hair",
  "hairType": "hair-curly",
  "categorySlug": "leave-in",
  "maxPrice": 1800000,
  "excludeIngredientSlugs": ["fragrance"]
}
```

پاسخ شامل `answer`، `products`، `currency`، `retrievalMethod`، `eligibleProducts`، `indexUpdatedAtUtc` و `isDemo` است. هر عضو products شامل **product** (جزئیات و تنوع‌ها)، **similarity** و **score** است. این ساختار جایگزین لیست ساده محصولات نسخه اولیه شده است.

## بازیابی و دانش

در شروع برنامه و هر ۳۰۰ ثانیه، سرویس پس‌زمینه دانش را از محصولات فعال بارگذاری می‌کند. تولید اولیه بردارها بسته به سخت‌افزار چند دقیقه زمان می‌برد. تا پایان این مرحله، مشاوره پاسخ ۵۰۳ می‌دهد. تعداد پیشرفت در `/api/knowledge/status` مشخص است.

بردارها به‌صورت batch تولید و در SQL ذخیره می‌شوند. در شروع‌های بعدی، محصول با هش محتوای یکسان از کش خوانده می‌شود. محصول‌های تغییرکرده بردار جدید می‌گیرند؛ تغییر قیمت و موجودی نیازی به تولید مجدد بردار ندارد، زیرا هنگام هر درخواست از SQL خوانده می‌شود. بازسازی ناموفق، snapshot قبلی را حفظ می‌کند.

ابتدا فیلترها روی همه نامزدهای SQL اعمال می‌شوند؛ سپس ترکیب شباهت برداری (۸۰٪) و هم‌پوشانی واژه‌ها (۲۰٪) مرتب می‌شود. انتخاب TopK پس از فیلتر انجام می‌شود. پارامترهای آن در بخش Rag تنظیمات هستند. `DocumentPrefix` و `QueryPrefix` نیز قابل تنظیم هستند؛ پیش‌فرض برای nomic است.

پس از تغییر نسخه داخلی مدل embedding با همان نام، `EmbeddingVersion` را تغییر دهید یا بازسازی `force=true` انجام دهید. نام یکسان مدل به‌تنهایی تغییر وزن‌های مدل را مشخص نمی‌کند.

متن مدل مولد، حتی با دستور محدودکننده، تضمین‌شده نیست. برای قیمت/موجودی و شناسه‌ها از داده ساختاریافته پاسخ استفاده کنید. کیفیت معنایی فارسی باید با پرسش‌های واقعی و مدل embedding مناسب‌تر نیز ارزیابی شود.

## مدیریت و خطاها

در Production یا اتصال غیرمحلی، بازسازی دستی بدون `Admin:ApiKey` فعال نیست و پاسخ ۵۰۳ می‌دهد. در Development و اتصال محلی، AJAX هم‌مبدأ می‌تواند بدون کلید بازسازی کند. کلید را از متغیر محیطی `Admin__ApiKey` یا secret configuration تأمین کنید و در فایل یا مخزن ثبت نکنید. هنگام بازسازی، آن را در هدر `X-Admin-Key` ارسال کنید. بازسازی خودکار کلید نمی‌خواهد. این کلید فقط مسیر نگهداری را محافظت می‌کند؛ API خواندن عمومی است و برای استقرار عمومی باید سیاست دسترسی متناسب با سرویس اضافه شود.

مشاوره برای هر IP حداکثر ۱۲ درخواست در دقیقه و بازسازی ۲ درخواست در دقیقه دارد. محدودیت در حافظه هر فرآیند است؛ استقرار چندنمونه‌ای به سیاست مشترک نیاز دارد. خطاهای سرویس به پاسخ کنترل‌شده ۴۰۰/۵۰۳/۵۰۴ تبدیل می‌شوند؛ جزئیات فنی فقط در گزارش سرور ثبت می‌شوند.

## تست و بازتولید داده

بیلد:

```powershell
dotnet build SkinRag.sln
```

در حالی که API روی پورت 52783 اجراست:

```powershell
python scripts/smoke_test.py
python scripts/smoke_test.py --chat
```

`--chat` علاوه بر فیلترها، درخواست واقعی Ollama برای پوست، مو و زیبایی ارسال می‌کند و تا آماده شدن ایندکس منتظر می‌ماند. برای آدرس دیگر `--base-url` بدهید. تست‌ها دیتابیس را تغییر نمی‌دهند و انتظار دارند داده seed موجود باشد.

بازتولید JSON و SQL از داده ساختگی قطعی:

```powershell
python database/generate_demo.py
```

خروجی: `database/seed-demo.sql`. داده مستقیماً در فایل SQL تولید می‌شود تا نسخه JSON تکراری نگه‌داری نشود. ابتدا generator را تغییر دهید و دوباره اجرا کنید. seed موجود به‌قصد حفظ ویرایش‌ها، محتوای SKUهای قبلی را بازنویسی نمی‌کند؛ برای داده تازه از SKUهای تازه استفاده کنید.

## صفحات وب

- `/chat`: چت کاربر نهایی با jQuery 4.0.0 و `$.ajax`، فیلترهای محصول، کارت تنوع‌ها، حالت انتظار، لغو درخواست، گفت‌وگوی جدید و پیام خطا. در موبایل فیلترها جمع می‌شوند. حداکثر ۴ پیام قبلی برای پرسش‌های پیگیری به API ارسال می‌شود. پیام‌ها فقط در حافظه همین صفحه‌اند و با بارگذاری مجدد پاک می‌شوند.
- `/admin`: آمار کاتالوگ، وضعیت اتصال SQL، مدل‌ها، پیشرفت ایندکس، کش، زمان آخرین بازسازی و رویدادهای نشست. بازسازی عادی و کامل با تأیید در صفحه انجام می‌شوند. وضعیت هر ۵ ثانیه و آمار هر دقیقه تازه می‌شوند.

صفحات با MVC و Razor در `Views/Pages/Chat.cshtml` و `Views/Pages/Admin.cshtml` قرار دارند. `Controllers/PagesController.cs` مسیرها را به View متصل می‌کند. قالب مشترک `Views/Shared/_Layout.cshtml` شامل ناوبری، فونت و فایل‌های مشترک است. Tag Helper فایل‌های CSS/JS را با نسخه محتوا بارگذاری می‌کند تا مرورگر نسخه قدیمی را نگه ندارد.

jQuery، CSS، JavaScript و فونت متغیر وزیرمتن با مجوز OFL داخل `wwwroot` هستند؛ صفحات برای اجرا به CDN یا ابزار build فرانت‌اند وابسته نیستند. اندازه متن اصلی و پیام‌ها ۱۶ پیکسل است. تمام فیلترها اختیاری‌اند و پیش‌فرض بدون انتخاب و بسته هستند؛ ارسال پیام به آماده‌شدن فهرست فیلترها وابسته نیست. مثال‌ها فقط متن پیام را پر می‌کنند. داده‌های سرور و پیام مدل به‌صورت متن نمایش داده می‌شوند و HTML دریافتی اجرا نمی‌شود. مسیر `/` به چت هدایت می‌شود و launch profile نیز چت را باز می‌کند.

سلام و جمله‌های اجتماعی بسیار رایج پاسخ سریع محلی دارند. عبارت‌های متنوع با مدل به `SMALL_TALK` و موضوعی مانند احوال‌پرسی، معرفی، محل زندگی یا برنامه روزانه هدایت می‌شوند؛ این مسیر جست‌وجوی محصول ندارد. درخواست محصول در پیام ترکیبی اولویت دارد و سابقه گپ از ارجاع معتبر محصول جدا نگه‌داری می‌شود. اگر منظور مشخص نباشد، سؤال روشن‌کننده متناسب پرسیده می‌شود. جزئیات و دستور ارزیابی با مدل واقعی در [راهنمای خط پردازش](docs/consultation-pipeline.md) آمده است.

پرسش‌های محصول ابتدا از تشخیص نیت و ساخت query می‌گذرند. سقف زمان مشاوره ۲۲۰ ثانیه و بردارسازی پرسش ۲۰ ثانیه است؛ زمان مرحله‌های مدل در `Consultation` تنظیم می‌شود. در صورت کندی یا قطع مدل پس از بازیابی موفق، خلاصه معتبر کاتالوگ با `responseMode: catalog` و توضیح شفاف نمایش داده می‌شود. AJAX حداکثر ۲۳۰ ثانیه منتظر می‌ماند و در موفقیت، خطا، لغو یا خطای نمایش پاسخ، کنترل ارسال آزاد می‌شود. پرسش کوتاه قیمت/جزئیات با ارجاع معتبر مستقیماً از SQL پاسخ می‌گیرد.

برای کاهش پردازش هر پرسش، واژه‌های جست‌وجو و طول بردار هر محصول فقط هنگام ساخت snapshot محاسبه می‌شوند. واژه‌های فارسی در یک مسیر مشترک با یکسان‌سازی «ی/ک»، فاصله‌ها و حذف اعراب پردازش می‌شوند. نام ترکیبات در رابط با Map خوانده می‌شود. چت در حالت آماده وضعیت را هر ۳۰ ثانیه و هنگام آماده‌سازی دانش هر ۵ ثانیه بررسی می‌کند.

بررسی مستقل تشخیص پیام خودمانی، حفظ پرسش محصول و پردازش متن (بدون دیتابیس یا Ollama):

```powershell
dotnet run --project tests/SkinRag.Checks
```

**دسترسی بازسازی:** در محیط Development و اتصال loopback محلی، بازسازی از AJAX هم‌مبدأ بدون کلید فعال است. درخواست باید JSON و دارای `X-Requested-With: XMLHttpRequest` باشد؛ Origin متفاوت رد می‌شود. در اتصال غیرمحلی یا محیط Production، کلید `Admin__ApiKey` لازم است. کلید پنل در مرورگر ذخیره نمی‌شود. با تنظیم کلید روی سرور، حتی دسترسی محلی نیز کلید می‌خواهد.

پنجره متن مدل در `Ollama:ContextWindow` و سقف توکن‌های تشخیص نیت، query و پاسخ در `Consultation` تنظیم می‌شود. پاسخ‌ساز فقط دو محصول برتر را دریافت می‌کند و کارت‌ها فقط محصولات معتبر نتیجه نهایی را نمایش می‌دهند. کدهای خروجی محدود مدل توسط C# به متن فارسی و اطلاعات جاری تبدیل می‌شوند؛ قیمت و مشخصات از SQL خوانده می‌شوند.

بررسی دیتابیس نمونه پس از seed:

```powershell
sqlcmd -S DESKTOP-JIRFTS7 -d SkinRagDb -E -C -b -f 65001 -i database/verify.sql
```
