# خط پردازش مشاوره

درخواست `POST /api/consultation/ask` از مسیر `InputNormalizer → InputGuard → IntentClassifier → QueryBuilder → ProductRetriever → RecommendationValidator` می‌گذرد. کنترلر فقط `ConsultationService` را صدا می‌زند؛ اتصال SQL در `Infrastructure/Persistence` و قرارداد مدل و مخزن محصولات در `Application/Abstractions` است. پرامپت‌ها در `Prompts` نگه‌داری می‌شوند.

## قرارداد و گفتگو

- `question` قبلی پشتیبانی می‌شود؛ `message` نیز پذیرفته می‌شود. اگر هر دو ارسال شوند باید یکسان باشند. پیام ۱ تا ۲۰۰۰ نویسه و تاریخچه حداکثر ۴ پیام است.
- `conversationId` اختیاری است و در پاسخ برمی‌گردد. برای پیگیری، همان شناسه را در درخواست بعدی بفرستید. ارجاع محصول فقط از نتیجه معتبر سرور گرفته می‌شود؛ پیام assistant در تاریخچه اجازه تعیین شناسه محصول را ندارد. حافظه گفتگو محدود به ۵۰۰ نشست با انقضای ۳۰ دقیقه پس از آخرین استفاده است و در دیتابیس ذخیره نمی‌شود.
- پاسخ، فیلدهای قبلی را حفظ می‌کند و `intent`، `intentConfidence`، `conversationId`، `recommendations`، `needsMoreInformation` و `followUpQuestion` را اضافه می‌کند. هر recommendation دارای `productId` و `reason` است.
- نیت‌ها: `GREETING`، `SMALL_TALK`، `SKIN_CONSULTATION`، `PRODUCT_SEARCH`، `PRODUCT_DETAILS`، `PRODUCT_COMPARISON`، `PRICE_INQUIRY`، `AVAILABILITY_INQUIRY`، `ROUTINE_RECOMMENDATION`، `FOLLOW_UP`، `OFF_TOPIC`، `UNSAFE`، `UNCLEAR`.
- پاسخ‌های اجتماعی دارای `conversationTopic` مانند `Wellbeing`، `Location`، `Identity` یا `DailyPlans` هستند. پاسخ مبهم دارای `clarificationKind` است تا نوع سؤال روشن‌کننده مشخص شود. این دو فیلد برای پاسخ‌های عادی محصول `null` هستند.

## مسیر و اعتبارسنجی

- سلام و جمله‌های اجتماعی بسیار رایج با قواعد محلی پاسخ می‌گیرند. عبارت‌های متنوع با تشخیص معنایی Qwen به دسته و موضوع گفتگو هدایت می‌شوند؛ فهرست جمله‌ها شرط پوشش کامل نیست. `SMALL_TALK` به SQL، embedding و جست‌وجوی محصول وارد نمی‌شود. موضوع اجتماعی مدل به متن کوتاه کنترل‌شده تبدیل می‌شود تا محل زندگی، بدن یا برنامه شخصی ساختگی برای دستیار تعریف نشود؛ برای پاسخ اجتماعی فراخوانی دوم مدل لازم نیست.
- درخواست صریح محصول در پیام ترکیبی اولویت دارد؛ «سلام خوبی؟ ضدآفتاب می‌خوام» درخواست محصول است. پرسش درباره خود دستیار، حتی اگر کلمه پوست یا مو داشته باشد، درخواست خرید محسوب نمی‌شود. سؤال نامرتبط عمومی همچنان `OFF_TOPIC` است.
- سابقه گپ (`RecentUserMessages`) از درخواست‌های معتبر محصول (`UserQuestions` و شناسه‌های نتیجه سرور) جدا است. سلام یا احوال‌پرسی به‌تنهایی سابقه محصول ایجاد نمی‌کند. مدل نیاز به سابقه را با `requiresContext` اعلام می‌کند؛ پیگیری محصول بدون سابقه معتبر با سؤال درباره نام/شناسه پاسخ می‌گیرد. گپ میان دو درخواست، شناسه محصولات قبلی را پاک نمی‌کند. تاریخچه assistant ارسالی از مرورگر منبع ارجاع معتبر محصول نیست.
- درخواست نامرتبط، ناامن، مبهم و اطمینان کمتر از حد تنظیم‌شده به SQL، embedding یا جست‌وجوی محصول وارد نمی‌شود. ابهام به سؤال روشن‌کننده درباره محصول، ترجیحات یا منظور کلی هدایت می‌شود؛ خرابی classifier نیز موجب درخواست توضیح بیشتر می‌شود. دسته، موضوع و نیاز به سابقه باید با هم سازگار باشند؛ خروجی ناسازگار مدل رد می‌شود.
- Query مدل فقط از slugهای معتبر استفاده می‌کند؛ فیلتر صریح کاربر مقدم است. بودجه عددی با واحد مشخص توسط C# خوانده می‌شود؛ تومان به ریال تبدیل می‌شود و بودجه مبهم نیازمند توضیح بیشتر است. «ارزان» موجب مرتب‌سازی اقتصادی میان نامزدهای مرتبط می‌شود. نیازهای خارج از واژگان دیتابیس فقط در متن جست‌وجو باقی می‌مانند.
- مقدار `maxPrice` در API و دیتابیس **ریال** است؛ عدد این فیلد دوباره تبدیل نمی‌شود. `BudgetParser` فقط متن کاربر را می‌خواند: «من ۲۰۰ هزار تومان دارم» به ۲٬۰۰۰٬۰۰۰ ریال و «۲۰۰ هزار ریال» به ۲۰۰٬۰۰۰ ریال تبدیل می‌شود. این سقف پیش از خواندن کاتالوگ در `QueryBuilder` به فیلتر اضافه می‌شود. فیلتر عددی صریح رابط بر مبلغ متن اولویت دارد. مبلغ منفی یا بالاتر از یک میلیارد ریال رد می‌شود و واحد نامشخص یا چند سقف متفاوت به سؤال روشن‌کننده می‌رسد.
- اگر پیام فقط بودجه باشد، دستیار مبلغ تبدیل‌شده را تأیید می‌کند و نوع محصول را می‌پرسد. بودجه در حافظه همان گفتگو برای درخواست بعدی نگه‌داری و پس از ثبت نتیجه محصول مصرف می‌شود؛ پیام بودجه به‌تنهایی جست‌وجو یا پیشنهاد محصول ایجاد نمی‌کند.
- جست‌وجوی عمومی فیلتر SQL، شباهت برداری و تطبیق واژه‌ها را ترکیب می‌کند. شناسه صریح مانند `#12` و پیگیری قیمت/موجودی محصول قبلی مستقیماً از SQL خوانده می‌شوند و به آماده‌بودن ایندکس نیاز ندارند. اطلاعات محصول ناموجود قابل پرس‌وجو است؛ پیشنهاد خرید به محصول فعال و موجود محدود می‌شود.
- تمام خروجی‌های مدل JSON هستند. JSON ناقص، کلید تکراری، فیلد اضافی، نیت نامعتبر، شناسه خارج از context و دلیل خارج از اطلاعات مجاز رد می‌شوند. موجودی، قیمت و فیلترها دوباره از SQL بررسی می‌شوند. متن مربوط به واقعیت‌های محصول و قیمت را C# از رکورد جاری می‌سازد؛ مدل فقط کد متن آغازین و دلیل مجاز را انتخاب می‌کند و C# آن را به متن فارسی تبدیل می‌کند. این محدودیت از ادعای درمان یا قیمت ساخته‌شده جلوگیری می‌کند و خروجی مدل محلی را کوتاه نگه می‌دارد.
- در خرابی QueryBuilder از فیلترهای صریح و متن کاربر استفاده می‌شود؛ در خرابی پاسخ‌ساز، خلاصه معتبر کاتالوگ با `responseMode: catalog` برمی‌گردد. زمان کل و زمان هر مرحله در `Consultation` تنظیم می‌شود. مدل‌های مستقل اختیاری `Ollama:IntentModel`، `Ollama:QueryModel` و `Ollama:ConsultationModel` در صورت نبود از `ChatModel` استفاده می‌کنند.
- قیمت، موجودی و ترکیبات اولیه کاتالوگ تأیید تجاری نشده‌اند؛ تغییر نام برند به معنی تأیید این مشخصات نیست.
- با مدل محلی ۷ میلیارد پارامتری، بارگذاری اولیه و تولید پاسخ روی این دستگاه کند است. مهلت تشخیص نیت ۷۰ ثانیه، ساخت query و پاسخ هرکدام ۶۰ ثانیه، کل مشاوره ۲۲۰ ثانیه و انتظار مرورگر ۲۳۰ ثانیه است؛ زمان‌ها قابل تنظیم‌اند. در timeout پاسخ مدل، خلاصه کاتالوگ معتبر همچنان قابل استفاده است. تغییر `ChatModel` تنها مدل پاسخ‌گو را تغییر می‌دهد؛ بردارهای جست‌وجو به `EmbeddingModel` و هش داده وابسته‌اند.

## بررسی

بررسی مستقل قراردادها، مسیرها، اطلاعات جاری و fallback:

```powershell
dotnet run --project tests/SkinRag.Checks
```

ارزیابی تشخیص معنایی با Ollama واقعی، بدون اجرای API و بدون دسترسی به دیتابیس، از ریشه پروژه:

```powershell
dotnet run --project tests/SkinRag.Checks -- --intent-live
```

این بررسی نمونه‌های عبارت متنوع، پیام ترکیبی، پیگیری بدون سابقه محصول و تغییر موضوع از محصول به گپ را می‌سنجد. نتیجه این نمونه‌ها تضمین تشخیص تمام جمله‌های ممکن نیست.

بررسی کامل با API اجراشده، SQL Server و Ollama واقعی، بدون نیاز به Python:

```powershell
dotnet run --project tests/SkinRag.Checks -- --live --base-url http://127.0.0.1:52783
```
